# CUT&Tag comparison of Vazyme and EpiCypher workflows

## Overview

This repository contains the analysis workflow used to compare CUT&Tag data generated with Vazyme and EpiCypher reagents. The analysis includes FASTQ preparation from BaseSpace exports, execution of the `nf-core/cutandrun` pipeline, BAM downsampling, peak calling with MACS2, blacklist filtering, and visualization of peak counts as a function of sequencing depth.

The repository is organized as a stepwise workflow so that each part of the analysis can be inspected, reproduced, and reviewed independently.

## Study aim

The goal of this analysis was to assess how sequencing depth affects peak detection in CUT&Tag data and to compare the behavior of Vazyme and EpiCypher samples across downsampling levels.

## Workflow summary

### 1. FASTQ preparation

`data_preparation/01_basespace_to_fastq.sh`

BaseSpace sample folders were merged into project-level FASTQ files for each sample and read pair.

### 2. Sample renaming

`data_preparation/02_sample_renaming.sh`

File names were standardized to maintain consistent sample labels across the analysis.

### 3. Primary CUT&Tag processing

`pipeline/03_run_nextflow.sh`

The main analysis was performed with `nf-core/cutandrun` using:

- Nextflow `24.10.0`
- `nf-core/cutandrun` `3.2.1`
- genome: `hg38`
- peak caller: `MACS2`
- normalization mode: `CPM`
- Docker profile
- no control sample

### 4. Test execution

`pipeline/04_nextflow_test.sh`

A test run was included to validate the workflow installation before processing the full dataset.

### 5. BAM downsampling

`downsampling/05_downsample_bams.sh`

Aligned BAM files were downsampled to 10 percent, 20 percent, up to 90 percent of the original reads using `samtools view -s`. BAM collation was performed before downsampling to preserve paired-end structure.

### 6. Peak calling post downsampling

`peak_calling/06_macs2_peak_calling.sh`

Downsampled BAM files were processed with MACS2 using paired-end mode and fixed fragment handling parameters.

### 7. Blacklist filtering

`peak_calling/07_blacklist_filter.sh`

Called peaks overlapping hg38 blacklist regions were removed with `bedtools intersect -v`.

### 8. Visualization

`analysis/08_peak_vs_depth_plot.R`

Peak counts were plotted against sequencing depth in R using `ggplot2`, comparing kit type and replicate.

## Notes on reproducibility

This repository preserves the original commands used in the analysis while restructuring them into reviewer-friendly modules. Several commands remain commented because they are tied to institution-specific storage paths, mounted resources, or manually triggered execution steps. These comments are intentionally retained to document the original analysis history without altering the underlying code.

For reuse on a different system, local paths should be adapted to the user environment.

- blacklist-filtered peak sets
- a figure showing peak counts across sequencing-depth fractions

## Suggested citation text for methods

CUT&Tag data were processed using `nf-core/cutandrun` with hg38 as the reference genome and MACS2 as the peak caller. To evaluate the effect of sequencing depth on peak detection, aligned BAM files were downsampled across a range of read fractions and reprocessed through MACS2. Peaks overlapping hg38 blacklist regions were removed using bedtools, and peak counts were visualized in R.
